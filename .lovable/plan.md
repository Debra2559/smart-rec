# 职场录音设备配套软件 — 整体方案

## 产品定位

一台 24 小时随身的"职场第二大脑"。两种录音形态，对应两种完全不同的数据契约和产品体验。

## 两种模式的核心区别

| | 低感录音（陪伴模式） | 深度录音（工作模式） |
|---|---|---|
| 运行方式 | 默认常开，全天候 | 用户主动开启/结束 |
| 音频文件 | 绝不落盘、不保存 | 完整保存，可回放 |
| 声纹/说话人 | 不做任何声纹处理 | 区分说话人（Speaker 1/2…，可命名） |
| 文字原文 | 不保存逐字稿 | 保存完整逐字稿，可检索 |
| 产出 | 结构化摘要：待办、情绪、事件时间线 | 摘要 + 决议 + 思维导图 + 逐字稿 |
| 隐私感 | 最高，用户可放心常开 | 明确的"正在录音"状态提示 |

低感模式的技术契约要写死在系统里：音频只在内存中流式处理，出摘要即丢弃；数据库里没有音频字段、没有原文字段。这是产品信任的根基，也是对外的主要卖点。

## 三大主界面

### 1. 今天（低感模式的主场）
一屏看完这一天：
- **待办清单**——从对话里自动提取的 to-do 与提醒，可勾选、可设提醒时间
- **情绪曲线**——一天的情绪走势，标注转折点（"14:20 与客户通话后压力上升"）
- **事件时间线**——按时间排布的事件卡片，只有摘要，没有原文
- **今日复盘**——晚间自动生成的一段回顾，语气像知乎长回答：有观察、有因果、有建议，而不是干巴巴的要点罗列

### 2. 会议（深度模式的主场）
每场深度录音是一个可深挖的工作单元：
- **音频播放器**——波形 + 跟随播放的逐字稿，点句子跳播
- **思维导图**——议题为中心向外展开分支，可折叠、可导出
- **结论与待办**——决议、负责人、截止时间
- **说话人标签**——首次命名后在后续会议中沿用
- **搜索**——跨所有会议的全文检索

### 3. 回顾
- **日历视图**——每天一格，密度色块表示当天录音与事件量，点进去看当日详情
- **周/月总结**——趋势：时间花在哪、情绪如何变化、哪些待办反复拖延
- **人物视图**（深度模式）——按合作对象聚合：和某人聊过什么、未完成的事项

### 4. 设置与隐私
设备状态、存储用量、模式开关、免打扰时段/地点、一键删除某天或全部数据、导出数据。隐私页面用人话说清楚"哪些数据存了、哪些从不存"。

## 分期路线

**第一期（打地基）**
- 三大主界面骨架 + 完整设计系统
- 用户登录、数据结构、隐私边界落库
- 低感模式全链路：音频流入 → 摘要 → 待办/情绪/时间线
- 深度模式：录音上传、转写、逐字稿、摘要

**第二期（变生动）**
- 思维导图、日历视图、说话人分离与命名
- 周/月总结、人物视图、全文搜索

**第三期（长出习惯）**
- 待办提醒与日程同步
- 设备端联动（电量、存储、同步状态）
- 跨天趋势洞察、导出分享

## 技术要点

- Lovable Cloud 提供数据库、登录、文件存储、服务端逻辑，无需外部账号
- 音频转写与内容理解走 Lovable AI（转写 + 结构化提取 + 摘要生成），全部在服务端执行
- 低感模式用一个只写摘要的服务端管线：转写结果只存在于单次请求内存里，写库时只落 `summaries` / `todos` / `emotion_points` / `events`，表结构本身不含 `audio_url` 与 `transcript` 字段，从数据模型层面保证"无法保存"
- 深度模式独立的 `recordings` / `transcript_segments` / `speakers` 表 + 存储桶，行级安全策略保证数据只对本人可见
- 所有摘要与提取通过结构化输出约束成固定 schema，保证前端渲染稳定

## 需要你确认的

1. 设备与软件怎么连——先做纯软件（手机录音 + 上传），还是一开始就按硬件同步来设计？
2. 是否需要团队/多人协作（共享会议记录），还是纯个人使用？
3. 低感模式的摘要频率——实时滚动，还是按小时/半天批量生成？

这三点不影响第一期开工，可以边做边定。
