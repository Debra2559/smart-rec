# 职场录音设备配套软件 — 整体方案 v2

## 产品定位

一台 24 小时随身的"职场第二大脑"：听得见会议、记得住生活、读得懂身体。四种能力叠加——双模式录音、健康数据关联、实时生成、AI 问答。

## 两种录音模式的核心区别

| | 低感录音（陪伴模式） | 深度录音（工作模式） |
|---|---|---|
| 运行方式 | 默认常开，全天候 | 用户主动开启/结束 |
| 音频文件 | 绝不落盘、不保存 | 完整保存，可回放 |
| 声纹/说话人 | 不做任何声纹处理 | 区分说话人（Speaker 1/2…，可命名） |
| 文字原文 | 不保存逐字稿 | 保存完整逐字稿，可检索 |
| 产出 | 结构化摘要：待办、情绪、事件时间线 | 摘要 + 决议 + 思维导图 + 逐字稿 |
| 隐私感 | 最高，用户可放心常开 | 明确的"正在录音"状态提示 |

低感模式的技术契约写死在系统里：音频只在内存中流式处理，出摘要即丢弃；数据库里没有音频字段、没有原文字段。这是信任的根基，也是主要卖点。

## 实时生成

深度录音打开即开始流式产出，不等结束：
- 逐字稿边说边出，跟随滚动
- 每几分钟滚动更新：当前议题、待办捕捉、情绪变化
- 会议结束后 30 秒内给出完整摘要、决议清单和思维导图

低感模式做"轻实时"：事件卡片和待办在一天中陆续浮现，晚间自动生成完整复盘。

## 健康数据关联

设备接收健康数据（参考 Apple Health / HealthKit 的数据面），并在"今天"页与当天事件做关联展示：

**接入的数据类别**
- 心脏：心率、静息心率、心率变异性（HRV）
- 活动：步数、锻炼时长、站立时长、活动能量、锻炼记录
- 睡眠：卧床时长、各阶段睡眠、醒来次数
- 其他：血氧、呼吸频率、正念分钟数

**关联方式（这是关键差异化）**
- 时间线叠加：压力事件旁边标出当时的心率尖峰；深度会议时段叠加 HRV 变化
- 因果提示："昨天下午的客户评审后，你的静息心率升高且当晚深睡减少 20%"
- 状态感知复盘：晚间复盘不只讲"发生了什么"，还讲"身体付出了什么"，并给出次日建议
- 健康数据只读、本地展示与关联分析；不写入医疗结论，只做生活方式层面的提示

## AI 问答助手

随时可问的个人助手，回答建立在用户自己的数据之上：
- "我这周答应过别人什么事？"——检索待办与会议决议
- "上次和 David 开会定了什么？"——跨会议检索逐字稿与摘要
- "最近睡得怎么样，和加班有关吗？"——健康 × 事件关联分析
- 支持语音提问，通勤路上也能用
- 问答引用来源：每条回答可点开看到出自哪场会议、哪条事件摘要

## 主界面结构

1. **今天**——待办、情绪曲线、事件时间线、健康指标叠加、晚间复盘
2. **会议**——实时转写、逐字稿播放器、思维导图、决议待办、说话人、全文搜索
3. **问答**——AI 助手对话界面，支持语音输入，答案带来源引用
4. **回顾**——日历视图、周/月总结（工作 × 健康趋势）、人物视图
5. **设置与隐私**——设备状态、存储、模式开关、免打扰、数据删除与导出、健康数据授权管理

## 市场竞争力分析

**对标现状**
- Plaud / iFLYTEK 录音卡：只做深度模式 + 摘要，无陪伴模式、无健康、无问答
- Limitless / Friend 类 AI 挂件：只做陪伴摘要，无工作级深度功能，无健康
- Apple Watch / 健康 App：有健康数据，但完全不理解你的工作和对话

**我们的独特位置**：唯一把"工作对话 + 生活事件 + 身体数据"三条线合成一个人模型的产品。别人卖记录工具，我们卖自我认知。

**需要补齐的功能（按优先级）**
1. **硬件与同步协议**——BLE/Wi-Fi 传输、增量同步、断点续传、设备存储管理；这是体验下限
2. **隐私与合规**——录音合法性提示（双人同意地区）、本地加密、合规声明模板；直接影响能否上架
3. **提醒闭环**——待办不是列出来就完事：到点推送、日历同步（Google/Outlook/飞书/钉钉）
4. **准确率兜底**——专有名词自学习词表（同事姓名、行业术语）、说话人纠错的低成本交互
5. **数据可携带**——一键导出（Markdown/PDF/音频包），降低用户锁定焦虑，反而提升信任
6. **可穿戴联动**——直接读取手表数据，减少对健康 App 中转的依赖
7. **团队场景**（可后置）——共享会议纪要、多人声纹库；B 端付费空间更大

**风险点**：续航（24h 录音对电池和散热要求极高）、音频上传成本与延迟、隐私口碑一次事故即崩盘——隐私架构必须先于功能上线。

## 分期路线

**第一期（打地基）**
- 五大界面骨架 + 设计系统、用户登录、数据结构、隐私边界落库
- 低感模式全链路：音频流入 → 摘要 → 待办/情绪/时间线
- 深度模式：录音上传、流式转写、实时逐字稿、摘要

**第二期（变生动）**
- 思维导图、日历视图、说话人分离与命名
- 健康数据接入与时间线叠加展示
- AI 问答模块（会议 + 事件 + 健康统一检索）

**第三期（长出习惯）**
- 待办提醒与日历同步、健康 × 事件关联洞察
- 周/月总结、人物视图、数据导出
- 设备端联动（电量、存储、同步状态）

## 技术要点

- Lovable Cloud：数据库、登录、文件存储、服务端逻辑，无需外部账号
- 转写与理解走 Lovable AI（流式转写 + 结构化提取 + 摘要），全部在服务端执行
- 低感模式只写摘要的服务端管线：转写结果只存在于单次请求内存；`summaries` / `todos` / `emotion_points` / `events` 表不含 `audio_url` 与 `transcript` 字段，从数据模型层面保证"无法保存"
- 深度模式独立的 `recordings` / `transcript_segments` / `speakers` 表 + 存储桶
- 健康数据独立 `health_metrics` 时序表，与事件按时间窗口做关联查询；行级安全策略保证数据只对本人可见
- AI 问答采用检索增强：先按用户召回相关摘要/逐字稿/健康指标，再生成带来源引用的回答
- 所有 AI 提取通过结构化输出约束成固定 schema，保证前端渲染稳定

## 需要你确认的

1. 设备与软件怎么连——先做纯软件（手机录音 + 上传），还是一开始就按硬件同步来设计？
2. 健康数据来源——通过 Apple Health / HealthKit 中转读取，还是设备自带传感器直采？
3. AI 问答的数据范围——只答个人数据，还是也允许联网通识问答？
4. 是否需要团队/多人协作，还是纯个人使用？

这四点不影响第一期开工，可以边做边定。
